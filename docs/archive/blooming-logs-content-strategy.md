# Blooming Logs 内容栏目与标签规则

## 目标

这份规则只解决三件事：

1. 每篇文章应该放进哪个栏目。
2. 哪些文章需要打 tag，tag 应该怎么收口。
3. 首页“精选文章”应该如何挑，不让首页慢慢滑回普通博客列表。

规则优先于直觉。拿不准时，宁可少打 tag、少设精选，也不要先把体系放散。

## 命名决策

从这一版开始，文档统一采用方案 B：

- `/archive` 保留为全站按时间浏览的总归档页，前台名称继续叫 `Archive`。
- 第六个内容栏目改名为 `Drawer`，用于承接“旧稿、回看、抽屉感内容”。
- 当前代码里仍有把栏目 id 写成 `archive` 的旧实现；文档先统一为目标命名，代码后续再迁移到 `drawer`。

## 字段分工

- `category`：回答“这篇文章放在哪一层架子上”，每篇只能有一个。
- `tags`：回答“这篇文章能和哪些别的文章串成一条线”，可以为空。
- `mood`：回答“这篇文章的气氛是什么”，不承担分类职责。
- `featured`：回答“这篇文章是否进入首页精选”，默认 `false`。

不要用 `tags` 代替 `category`，也不要让 `featured` 变成“我最近很喜欢这篇”的情绪按钮。

## 栏目定义

### Notes

用于日常随记、个人想法、写作开场、短札记、没有更明确对象的记录。

适合：

- 第一人称的个人文章
- 对项目、写作、生活状态的短反思
- 站点开场文、写作说明文

不优先放这里：

- 明显是技术实验过程的文章
- 明显围绕声音或视觉对象展开的文章

### Lab

用于代码、AI、工作流、实验、方法论、工具观察。

适合：

- 对 Agent、工具链、工作流的拆解
- 项目实验笔记
- 技术判断、方法比较、失败记录

不优先放这里：

- 只是提到技术，但核心是日常感受的文章

### Records

用于声音、音乐、歌单、专辑、听觉经验、声音触发的记忆。

适合：

- 听歌笔记
- 专辑、歌单、声音设备记录
- 由声音切入的感受

不优先放这里：

- 只是“顺手提到一首歌”的文章

### Frames

用于视觉对象、照片、电影、界面、镜头感、图像观察。

适合：

- 电影或照片相关记录
- 视觉界面观察
- 由画面和镜头感展开的文章

不优先放这里：

- 只是用了图片举例，但主题仍然是技术或日常随记的文章

### Garden

用于季节、植物、天气、窗边观察、柔软感受、慢观察。

适合：

- 花、海风、云、光线、季节变化
- 没有强结论压力的轻记录
- 想给站点留出“缓和区域”的文章

不优先放这里：

- 明显要进入技术讨论或项目总结的文章

### Drawer

用于旧稿、旧纸张、回看、抽屉感内容，而不是单纯按时间归档。

适合：

- 带“回望”意味的文章
- 旧笔记整理、旧观点再看
- 不一定是最新，但值得保留的旧内容

不优先放这里：

- 只是发布时间比较早的文章
- 暂时不知道该放去哪里的文章
- 主体其实是技术、音乐、视觉或日常记录，只是顺手提到“过去”的文章

说明：

- `/archive` 页面是全站按时间的总归档。
- `Drawer` 是六个内容栏目之一，目标 `category` 值为 `drawer`。
- `Drawer` 不是时间页，它是带编辑立场的内容栏目。

## 栏目选择顺序

拿不准栏目时，按下面顺序判断：

1. 这篇文章最强的对象是什么：人、实验、声音、画面、季节，还是旧内容。
2. 如果删掉正文里最吸引人的那一层，这篇文章还剩什么。
3. 优先看文章“真正围绕什么展开”，不要看它顺手提到了什么。

如果一篇文章既像 `Notes` 又像别的栏目，优先把它放进那个更具体的栏目，而不是一律落回 `Notes`。

## Tag 规则

### Tag 的职责

tag 只用来连接跨栏目主题线，不用来做搜索关键词堆叠。

一个好 tag 应该满足：

- 至少能把两篇文章连起来
- 未来大概率还能继续写
- 放到卡片或文章页上不会显得啰嗦

### 当前正式 tag 池

第一版先只保留这 6 个正式 tag：

- `Agent`
- `Workflow`
- `Memory`
- `Multimodal`
- `Voice`
- `Site`

### 使用规则

- 每篇文章最多 `2` 个 tag。
- 没有明显合适的 tag 时，允许留空。
- `Site` 只给站点建设、写作结构、博客自述类文章。
- `Workflow` 只给“过程、分工、执行链路”是核心的文章。
- `Memory` 只给长期记忆、状态保留、检索策略类文章。
- `Multimodal` 只给图像、界面、视觉理解跨模态问题是核心的文章。
- `Voice` 只给语音、音频、实时口语交互是核心的文章。
- `Agent` 只在文章确实属于 Agent 主题主线时使用，不要因为提到一次就打。

### 暂不使用的 tag 类型

第一版不要再新增下面这些类型：

- 一次性关键词
- 人名或个人代号
- 与栏目重名的 tag，比如 `Garden`、`Notes`
- 过细的技术名词，除非已经决定做成系列
- 纯情绪词，情绪应该交给 `mood`

### 新增 tag 的准入规则

只有满足下面至少一条，才允许加新 tag：

1. 你已经明确计划让它在接下来至少 3 篇文章里出现。
2. 它对应一条要长期写的系列线，而现有 tag 无法承载。

新增时保持：

- 英文
- Title Case
- 1 到 2 个词
- 能直接显示在前台，不像内部数据库字段

## 精选文章规则

### 精选的职责

`featured` 只服务首页策展，不代表“这篇最重要”或“这篇最新”。

### 第一版精选数量

首页长期保持 `3` 篇精选，不多不少。

### 三个角色

三篇精选最好分别承担这三种角色：

1. 入口文：告诉人这个站是什么、为什么存在。
2. 代表作：最能代表你当前真正想写的核心主题。
3. 气质文：让首页保留人的温度，而不只是项目说明。

不要让两篇文章承担同一种角色。

### 不适合设为精选的情况

- 只是因为它最新
- 只是因为它篇幅长
- 和另一篇精选承担同样入口功能
- 还明显带示例稿、占位稿、测试稿气味

## 新文章提交前检查

- 这篇文章的 `category` 是否比 `notes` 更具体。
- tag 是否可以减到 0 到 2 个。
- tag 是否来自正式 tag 池。
- `mood` 是否只表达气氛，而不是重复分类。
- `featured` 是否真的有首页职责，不是顺手设成 `true`。

## 第一版内容系统完成标准

- 六个栏目都有至少 1 篇像它自己的文章。
- `Notes` 和 `Lab` 各至少有 2 篇。
- 首页固定 3 篇精选。
- 正式 tag 总数不超过 6 到 8 个。
- 新文章默认先服从现有体系，不为单篇文章扩字段或扩 tag。
